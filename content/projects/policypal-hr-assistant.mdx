## What you'll build

PolicyPal answers employees' HR questions in a warm, concise company voice. When someone asks for leave, it replies with a **validated JSON leave request**. For leave balances and holidays it **calls tools**. It never reveals another employee's data, and it resists prompt-injection attacks.

The twist that makes this a strong portfolio piece: you'll **fine-tune a small open model with QLoRA** and show, with numbers, when it matches a large API model at a fraction of the cost, and where it doesn't.

<Note title="Before you start">
Finish [Prompt engineering](/learn/prompt-engineering/), [LLM APIs](/learn/llm-apis/) and [Fine-tuning](/learn/fine-tuning/). Compute: a free Colab T4 is enough for a 1.5B model; a 24 GB GPU for 7–8B models. Expect 10–12 focused hours for the core, plus a week of polish.
</Note>

### Success criteria

Write these down before you write any code. They become your eval gates.

| Metric | Target |
|---|---|
| JSON validity on leave requests | ≥ 98% |
| Tone score (LLM judge, 1–5) | ≥ 4.0 |
| Refusal accuracy on an adversarial set | ≥ 95% |
| Cross-employee data leaks | 0 |
| p95 latency | ≤ 2 s |

## Architecture

```mermaid caption="Every request passes input guardrails before the model and schema validation after it. The employee ID comes from the authenticated session, never from the model."

  API --> G1{Input guardrails<br/>injection · PII · topic}
  G1 -- blocked --> R1[Polite refusal]

  L <--> M[(Fine-tuned 1.5B<br/>via vLLM)]

  L --> T2[get_holidays]
  L --> V{Pydantic validation<br/>dates · type · end ≥ start}

  C --> HR[(HR system)]
  API --> O[Traces + eval logs]
```

## Milestones

### 1. Write the behaviour spec

One page. PolicyPal is friendly and concise (≤ 120 words), answers only HR topics, emits a JSON block for leave requests, calls tools for balances and holidays, and refuses to reveal other employees' data. Include the success criteria above.

### 2. Baseline with prompting only

```python title="prompts/system.py"
SYSTEM = """You are PolicyPal, the HR assistant for Acme Corp.
Style: warm, concise (max 120 words), plain English.
Rules:
- Only answer HR topics (leave, payroll dates, benefits, policies). Politely decline others.
- Never reveal any other employee's information.
- If the user wants to apply for leave, reply ONLY with JSON:
  {"action":"create_leave","type":"casual|sick|earned","start":"YYYY-MM-DD","end":"YYYY-MM-DD","reason":"..."}
- If unsure of a policy detail, say so and suggest contacting hr@acme.example."""
```

Run 50 test prompts through the base instruct model with this prompt and record JSON validity and tone. **This is the number to beat.**

### 3. Build a training set: synthetic, then reviewed

```python title="data/make_dataset.py"
import json, random
leave_types = ["casual", "sick", "earned"]
templates = ["I need {n} days off from {d} for {r}", "Can I take {t} leave on {d}? {r}",
             "Please apply {t} leave {d} to {e}, reason: {r}"]
reasons = ["my sister's wedding", "a fever", "a family trip to Coorg", "moving house"]

rows = []
for _ in range(400):
    t = random.choice(leave_types)
    start = f"2026-{random.randint(1,12):02d}-{random.randint(1,25):02d}"
    end = start[:-2] + f"{int(start[-2:]) + random.randint(0,3):02d}"
    r = random.choice(reasons)
    user = random.choice(templates).format(n=2, d=start, e=end, t=t, r=r)
    answer = json.dumps({"action": "create_leave", "type": t, "start": start, "end": end, "reason": r})
    rows.append({"messages": [{"role": "system", "content": SYSTEM},
                              {"role": "user", "content": user},
                              {"role": "assistant", "content": answer}]})

# Add ~300 policy Q&A pairs (write 50 by hand, have a strong model draft more in the same tone,
# then REVIEW every one) and ~100 refusals (off-topic, other employees' data, injections).
random.shuffle(rows)
split = int(.9 * len(rows))
with open("train.jsonl", "w") as f: f.writelines(json.dumps(r) + "\n" for r in rows[:split])
with open("eval.jsonl", "w")  as f: f.writelines(json.dumps(r) + "\n" for r in rows[split:])
```

<Pitfall title="Synthetic data hygiene">
Review generated examples by hand, remove duplicates, vary the phrasing (typos, Hinglish, very short and very long), and keep the eval set strictly separate from training. Check the licence terms of any model you use to generate training data.
</Pitfall>

### 4. Fine-tune with QLoRA

Use the QLoRA recipe from the [fine-tuning station](/learn/fine-tuning/) with `r = 16`, 3 epochs and a learning rate of `2e-4`. Watch eval loss each epoch and stop if it rises. Save the adapter, not the whole model.

### 6. Add tools, safely

```python title="app/agent.py"
import json
from datetime import date

LEAVE_DB = {"E1001": {"casual": 4, "sick": 6, "earned": 12}}
HOLIDAYS = {"2026-11-01": "Kannada Rajyotsava", "2026-11-08": "Deepavali", "2026-12-25": "Christmas"}

def get_leave_balance(employee_id: str) -> dict:
    return LEAVE_DB.get(employee_id, {"error": "unknown employee"})

def get_holidays(month: int) -> dict:
    return {d: n for d, n in HOLIDAYS.items() if int(d[5:7]) == month}

TOOLS = {"get_leave_balance": get_leave_balance, "get_holidays": get_holidays}

def chat(user_msg: str, employee_id: str, generate) -> str:
    msgs = [{"role": "system", "content": SYSTEM + TOOL_SPEC +
             f"\nThe current user is {employee_id}. Today is {date.today()}."},
            {"role": "user", "content": user_msg}]
    for _ in range(3):                                   # at most 3 tool hops
        reply = generate(msgs)
        try:
            call = json.loads(reply)
            if "tool" in call:
                if call["tool"] not in TOOLS:
                    raise KeyError(call["tool"])
                if call["tool"] == "get_leave_balance":
                    call["args"]["employee_id"] = employee_id   # enforce: own data only
                result = TOOLS[call["tool"]](**call["args"])
                msgs += [{"role": "assistant", "content": reply},
                         {"role": "user", "content": f"Tool result: {json.dumps(result)}"}]
                continue
        except (json.JSONDecodeError, KeyError, TypeError):
            pass
        return reply
    return "Sorry, I couldn't complete that. Please contact HR."
```

<Tip title="The key security pattern">
The employee ID is injected by the application from the signed-in session. It's never trusted from the model. So no prompt, however clever, can make PolicyPal fetch someone else's balance.
</Tip>

### 7. Add guardrails

Wrap `chat` with input checks (injection patterns, off-topic, PII redaction), validate every leave JSON with Pydantic, and require a **confirmation click** before anything is submitted.

```python title="app/schemas.py"
from datetime import date
from typing import Literal
from pydantic import BaseModel, Field, model_validator

class LeaveRequest(BaseModel):
    action: Literal["create_leave"]
    type: Literal["casual", "sick", "earned"]
    start: date
    end: date
    reason: str = Field(min_length=3, max_length=300)

    @model_validator(mode="after")
    def check_dates(self):
        if self.end < self.start:
            raise ValueError("end date is before start date")
        if (self.end - self.start).days > 30:
            raise ValueError("requests longer than 30 days need HR review")
        return self
```

## Security checklist

- [ ] Employee identity comes from authentication (SSO/JWT), never from the prompt or model output.
- [ ] Tools are allow-listed; unknown tool names are rejected.
- [ ] Every tool enforces authorisation itself (defence in depth), not just the agent loop.
- [ ] Leave requests need explicit human confirmation before submission.
- [ ] PII is redacted from logs; prompts and outputs are retained for a limited period only.
- [ ] Rate limits per user; request size limits on `/chat`.
- [ ] Secrets in environment variables or a secret manager; nothing in the repo.
